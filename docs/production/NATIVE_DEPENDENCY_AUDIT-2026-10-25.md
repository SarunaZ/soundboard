## FFmpeg shipped by `react-native-audio-api`

The baseline has `react-native-audio-api@0.13.2`. Its Android Gradle source includes `android/src/main/jniLibs` unless `disableAudioapiFFmpeg=true`, and its `preBuild` task invokes `scripts/download-prebuilt-binaries.sh`. That script pins `https://github.com/software-mansion-labs/rn-audio-libs/releases/download/v3.1.0/jniLibs.zip`; it downloads and unpacks the ZIP with curl/unzip and does not verify a checksum. The source manifest does not record a downloaded asset digest.

The package's checked-in headers and `.pc` metadata identify FFmpeg 8.0-era library ABIs (`libavcodec` 62.11.100, `libavformat` 62.3.100, `libavutil` 60.8.100, `libswresample` 6.1.100). **Those header versions alone cannot prove the exact upstream FFmpeg patch release of a binary.** The older candidate APK at `data/play-readiness-release-20261025-final/artifacts/soundboard-play-testing-unsigned.apk` contains `libavcodec.so`/`libavformat.so` for arm64 and x86_64, with `Lavc62.11.100` / `Lavf62.3.100` strings. Its embedded release metadata points to source commit `6e17e875d95714ce6b078935be8c1047b5e8e265`, before current dependency remediation; it is superseded by the r3 APK/AAB. The r3 artifact records per-ABI FFmpeg library hashes and provenance; those packaged bytes match the validated source-build outputs. The standalone probe reports `av_version_info()`; app-loaded runtime behavior still needs installed-app QA.

The Android module makes FFmpeg optional at build time, but it is enabled by default. `NodeOptionsParser.h` marks `.mp4`, `.m4a`, `.aac`, `.m3u8`, HTTP URLs, and detected MP4/M4A/AAC/M3U8 buffers as requiring FFmpeg. The Play editor accepts picked media and `app-play/src/media/localAudio.ts` stages a selected file and calls `AudioContext.decodeAudioData(stagedFile.uri)`; therefore a user-selected local media file reaches native parsing. This is a user-interaction boundary with file-size, duration, memory and timeout limits in app code, not proof of exploitability or protection against parser flaws.

The official [FFmpeg security page](https://ffmpeg.org/security.html) lists fixes in FFmpeg 8.0.1 for CVE-2025-63757 and CVE-2025-69693, 8.0.2 for CVE-2025-67306, and 8.0.3 for CVE-2026-8461 and CVE-2026-30999. The [official download page](https://ffmpeg.org/download.html) identifies FFmpeg 8.0.3 as the latest 8.0 branch release and lists library versions ending in `.103` (including `libavcodec 62.11.103` and `libavformat 62.3.103`). The earlier APK's `.100` strings establish older ABI-version values, but not by themselves the source release or which CVEs are exploitable in that artifact. The replacement source build now has pinned provenance, standalone x86_64 decoder evidence, and r3 APK/AAB package-hash checks. Full Play import-flow and physical-device evidence remain release gates. npm audit does not cover these native components.

### Upstream update availability checked 25 Oct 2026

The official [`rn-audio-libs` releases](https://github.com/software-mansion-labs/rn-audio-libs/releases) show `v4.0.0` as latest. Its release notes say the binaries are unchanged from `v3.2.0`; `v3.2.0` says the FFmpeg 8.0.1 headers were added, while the binaries are unchanged from `v3.1.0`. The current official [`react-native-audio-api@0.13.6` Android downloader](https://github.com/software-mansion/react-native-audio-api/blob/0.13.6/packages/react-native-audio-api/scripts/download-prebuilt-binaries.sh) still pins `v3.1.0` for Android binary assets. Thus an ordinary 0.13.x package upgrade or using the latest helper release does not supply updated FFmpeg Android binaries. The upstream release page offers a SHA-256 for the v4 `jniLibs.zip`, useful for integrity of that old artifact, not evidence it contains a patched FFmpeg build. No official 8.0.3 Android prebuilt was found in the release list during this audit.

The purpose-built FFmpeg 8.0.3 Android source build in [`scripts/native-ffmpeg/build-android.sh`](../../scripts/native-ffmpeg/build-android.sh) succeeded. Its script SHA-256 is `7372c0d83a2c620b8715b92feb8f5aa6c61965675f822b3dce0136da05d47eaf`; it pins official source SHA-256 `6136812ea6d4e68bdba27e33c2a94382711cdf4f8602ffef056ff792bd6f9818` and signing fingerprint `FCF986EA15E6E293A5644F10B4322F04D67658D8`, NDK `27.1.12297006`, Android API 24, Ubuntu Clang 18.1.3, and arm64-v8a/x86_64. The exact configure flags, library hashes, toolchain and validation claims are in [`provenance.json`](../../data/native-ffmpeg-8.0.3-final/provenance.json) and [`SHA256SUMS`](../../data/native-ffmpeg-8.0.3-final/SHA256SUMS). Network protocols/OpenSSL are disabled and only the local file protocol is enabled. The build checks ELF ABI class/machine, `DT_NEEDED`, and every `PT_LOAD` alignment at or above 16 KB.

The reduced configuration enables AAC, MOV/MP4/M4A, MP3, FLAC, CAF and WAV demuxing, but does not enable HLS. `NodeOptionsParser.h` still routes `.m3u8` and remote HTTP URLs to FFmpeg, yet this local build cannot process them because network protocols and the HLS demuxer are excluded. The Play picker/import flow is local-file only and only advertises its supported local media/audio types; remote URLs and HLS are intentionally outside the shipped Play feature scope. Do not imply this build supports the general Audio API's remote/HLS capabilities.

The Android x86_64 standalone runtime probe reports `8.0.3-soundboard-android-8.0.3`, `libavcodec 62.11.103`, and `libavformat 62.3.103`. Seven synthetic AAC/M4A/MP3/WAV mono/stereo fixtures decoded with sample counts matching the reference; the MP3 fixed-vs-float peak delta was below 1/32768. Empty WAV and malformed M4A fixtures were rejected with exit code 1 under a 10-second guard, and the probe did not hang. Results are in [`android-decodes.jsonl`](../../data/native-ffmpeg-qa-20261025/android-decodes.jsonl), [`android-decodes.stderr.log`](../../data/native-ffmpeg-qa-20261025/android-decodes.stderr.log), and [`primary-validation.log`](../../data/native-ffmpeg-qa-20261025/primary-validation.log). The successful r3 APK/AAB contain 16 FFmpeg library instances whose hashes matched validated build outputs; each artifact passed ELF alignment checks on 44 native libraries and the APK passed zipalign. See [packaged hash report](../../data/play-readiness-security-20261025-r3/artifacts/packaged-native-ffmpeg-sha256.txt) and [primary verification](../../data/play-readiness-security-primary-verification-20261025.log). A separate arm64 standalone probe on a Samsung Galaxy S24 Ultra also decoded seven synthetic fixtures; its records are local under `data/phone-readiness-20261025-r3/`. Bounded app install/import/editor flows on that phone are documented in [phone QA](PHONE_QA-2026-10-25.md), but the standalone probe is not evidence that the installed app loaded those native libraries. No physical 16 KiB device test was performed.

Remaining native checks are:

The bounded Samsung app QA and separate arm64 probe are recorded in [phone QA](PHONE_QA-2026-10-25.md); the standalone probe is not app-loaded decoder evidence and does not cover a physical 16 KiB device.

## Scope and limitations

- npm audit scans JavaScript package advisories; it does not scan FFmpeg `.so` binaries, Android Maven artifacts, NDK-built components, or APK contents.
- The standalone FFmpeg 8.0.3 build/probe, current r3 packaged hash/alignment checks, and bounded Samsung app import/editor flows are evidenced. The app-flow record does not establish direct evidence of which native decoder libraries the installed app loaded, nor broad physical compatibility. This does not prove exploitability or cover every decoder/demuxer.
- The verified r3 APK/AAB are unsigned and built from dirty source commit `6e17e875d95714ce6b078935be8c1047b5e8e265`; their build/source/toolchain provenance is recorded in `release-info.txt`. Final native attribution and Maven license review remain open.
