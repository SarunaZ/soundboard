## Current prototype revision

The prototype-only `PrototypeYoutubeRequestFactory` adds `--fixup never` to the
download request. Metadata and common request options are unchanged. This
prevents the problematic automatic `m4a_dash` fixup; it does not add an FFmpeg
CLI executable, cookies, authentication, proxies, access bypasses, or an
extractor update. The app does bundle native FFmpeg shared libraries through
`react-native-audio-api`. The prototype uses wrapper `0.18.1` and bundled
yt-dlp `2025.11.12`.

The previous phone report (timestamp `1791724199060`, 16:09:59 local) showed
`DOWNLOAD` / `ERR_SBYT_DOWNLOAD_EXTRACTOR` and
`YoutubeDLException: ERROR: 'NoneType' object has no attribute 'lower'`. The
report was retrieved at 16:10:27 local; that timestamp is historical, not a
fresh failure. An offline reproduction with the exact cached AAR and a
synthetic empty fixture traced the likely cause to the wrapper passing a truthy
missing `--ffmpeg-location`: yt-dlp reports FFmpeg available with
`basename=None`, then default `m4a_dash` fixup crashes in
`configuration_args` at `exe.lower()`. A separate full `process_info`
comparison reproduced that failure with default `detect_or_warn` and returned
without the fixup under `--fixup never`. This strongly supports the hypothesis,
but does not prove the phone's exact container or successful phone extraction.
See [yt-dlp PR #15104](https://github.com/yt-dlp/yt-dlp/pull/15104), merged
after the bundled version.
